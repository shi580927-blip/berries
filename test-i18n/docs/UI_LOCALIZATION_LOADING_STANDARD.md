# Безумные ягодки — стандарт UI-локализации, атласов и быстрой загрузки

Дата: 2026-09-27  
Статус: обязательный production-стандарт для дальнейшей разработки.

## 1. Приоритет до локализации

До начала EN/TR обязательно завершить:
1. оптимизацию холодного старта и проверить реальное время первого запуска;
2. заменить Королевскую лавку на чистый localizable production popup;
3. реализовать ежедневные награды;
4. прогнать regression/checklist после этих изменений.

Только после этого начинать системный перевод RU → EN → TR.

## 2. Декоративный текст vs runtime-текст

### Как графика / PNG / atlas
Использовать для элементов, где внешний вид является частью арт-дирекшна:
- крупные декоративные заголовки;
- стилизованные подписи кнопок;
- названия разделов;
- фирменные надписи с неровной/округлой декоративной типографикой;
- текст, который стандартный web-font не воспроизводит визуально на нужном уровне.

Для локализации такие элементы готовятся отдельно по языкам и складываются в текстовые атласы.

### Кодом
Оставлять всё динамическое:
- цены из SDK;
- валюту/portal currency;
- числа;
- счётчики;
- таймеры;
- прогресс целей;
- статусы покупки;
- временные системные сообщения;
- значения, которые меняются от платформы, пользователя или состояния игры.

Нельзя запекать SDK-цену/валюту в универсальный PNG.

## 3. Схема атласов

Не собирать один гигантский atlas на всю игру.

Рекомендуемая структура:
- atlas_ui_common — общие кнопки, рамки, небольшие декоративные UI-элементы;
- atlas_popup_common — общие части поп-апов;
- atlas_text_ru — декоративные RU-надписи;
- atlas_text_en — декоративные EN-надписи;
- atlas_text_tr — декоративные TR-надписи;
- при необходимости отдельные небольшие тематические atlas для коллекции/ивентов.

Общие иллюстрации и фоны не дублировать между языками.
Локализованный текстовый atlas загружать только для выбранного языка.

## 4. Королевская лавка

Целевое состояние:
- один красивый clean popup без вшитых текстов и цен;
- отдельные пустые выпуклые кнопки/слоты в artwork;
- заголовки/декоративные подписи — localized PNG/atlas, если кодовый шрифт не даёт нужного качества;
- цена и currency icon — только из platform SDK;
- hit-zones привязаны к геометрии кнопок;
- close hit-zone совпадает с нарисованным крестиком;
- один layout для RU/EN/TR.

## 5. Быстрый первый запуск

Минутный холодный старт недопустим.

Правило:
- первый визуальный экран должен появляться максимально быстро;
- до первого экрана грузятся только critical assets;
- остальной core грузится в фоне после появления заставки;
- тяжёлые будущие разделы (коллекция, события, seasonal content) загружаются лениво при необходимости;
- музыка не должна блокировать первый кадр;
- cloud/player sync не должен скрывать уже готовую заставку;
- вход в карту/gameplay допускается только после безопасного восстановления прогресса.

## 6. Реализованная fast-boot схема 2026-09-27

- удалён fullscreen startup gate, который скрывал canvas ради старой проблемы с 50% iframe;
- ResizeObserver сохранён и вызывает несколько быстрых Phaser scale.refresh() после изменения контейнера;
- Boot блокируется только на title background + logo + main button;
- map/gameplay/UI/SFX догружаются в фоне уже на Title;
- Yandex player/cloud restore стартует в фоне;
- переход в Map ждёт окончания core preload + cloud restore + digits font;
- игрок видит красивый стартовый экран вместо полноэкранной «Загружаем лес…».

## 7. Проверка производительности

Проверять отдельно:
- Yandex draft, холодный cache;
- повторный запуск;
- Android Yandex Browser;
- iPhone Safari/WebView;
- desktop;
- slow network.

Замерять:
- время до первого видимого экрана;
- время до доступности кнопки «Играть»;
- время до Map;
- размер фактически загруженных данных до первого экрана;
- отсутствие 50%-масштаба/скачка canvas;
- отсутствие минутного зависания.

После замеров дополнительно решать, какие группы переводить в atlases/WebP и какие экраны загружать lazy.
