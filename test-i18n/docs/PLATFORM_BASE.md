# Общая база и будущие платформы

15.10.2026. Каноническая ветка разработки — `base`, без SDK. Основа — альфа 3b55807. Бета и её визуальные эксперименты не используются. Молния отдельно сохранена в docs/SPECIAL_BERRY_LIGHTNING.md как идея/код на будущее, сейчас не подключена.

## Что проверено
- В index.html нет /sdk.js; код Яндекс-адаптера из base удалён.
- Все обращения сцены/экономики/пауз идут через BerriesPlatform.
- Локальный адаптер не обращается к SDK, сети, облаку или платёжным окнам.
- Ключи и схема локального прогресса сохранены; прогресс на прежнем origin не сбрасывается. На новом origin браузерное хранилище будет другим.
- Магазин за игровые монеты и ежедневный подарок работают по прежней экономике.
- Реклама и реальные покупки не дают фиктивных наград. В win/lose rewarded-кнопки отключены, показана недоступность. Цены платной лавки не подставляются из кода.
- Число уровней, цели, поля, координаты главной кнопки и номера уровня не менялись.
- Автоматические проверки: campaign, special-label-lifecycle, platform. Полный визуальный тест в браузере пока не выполнен.

## Подключение адаптера

По одному адаптеру на сборку, выбранному явно до загрузки platform.js:

```html
<script>window.BerriesPlatformConfig = { platform: 'vk' };</script>
<script src="src/platform/platform.js"></script>
<script src="src/platform/vk.js"></script>
```

Файл vk.js (в будущем) регистрирует `BerriesPlatform.register('vk', factory)`. local.js заменяется нужным файлом. Если адаптер не загружен, запуск выдаст явную ошибку; случайного переключения на другую платформу нет. Зарегистрировать адаптер нужно до Boot/init. Поведение дополнительно определяется capabilities: cloud, rewarded, purchases.

Интерфейс адаптера:
- init(), getLanguage() — язык выбранной платформы; сейчас поддерживается только RU, остальные получают RU fallback.
- loadingReady(), gameplayStart(), gameplayStop() — платформенный lifecycle.
- restoreProgress(), saveProgress(snapshot), flushProgress() — облако при наличии. LocalStorage остаётся собственностью campaign; нельзя заменять его пустым облаком до успешного чтения.
- showRewardedVideo() — Promise<boolean>; true только после реального onRewarded, не после открытия/закрытия рекламы. Facade владеет паузой, защитой повторного нажатия, проверкой доступной награды и cooldown 2 минуты после успешного просмотра. Он сам не начисляет reward: результат используют существующие одноразовые операции Campaign.
- getPurchaseCatalog(), purchaseProduct(id), restorePurchases() — нормализованные товары/результат. Проверка оплаты, восстановление незавершённых транзакций, выдача ровно один раз, надёжное сохранение до подтверждения/погашения — ответственность будущей интеграции. Local возвращает пустой каталог и unavailable.

Не подключать два SDK одновременно. Логику конкретного портала не размещать в игровых сценах. Существующие product ID — доменные идентификаторы наград, наличие их в campaign не означает подключённые платежи.

## Отдельные версии, позже

От `base` создаются платформенные версии: VK, Одноклассники, Яндекс, GamePush. Здесь они ещё не созданы и не объявлены готовыми. Для VK/ОК сначала определить фактический способ запуска и адаптер. Для Яндекса использовать alpha как справочник проверенной интеграции, затем повторить реальные проверки. Для GamePush — реализовать его адаптер по актуальной документации. Перед каждым выпуском сверять актуальные требования выбранной площадки и её реальные рекламные/платёжные сценарии.

## Архивные файлы

В репозитории остаются старые неактивные runtime_fixes и исторические документы: они не подключаются index.html и не попадают в production allowlist. Замороженная alpha содержит прежний Яндекс-код и платформенные тесты; source main не переписывается. В дальнейшем доработки игрового ядра ведутся в base; платформенные версии получают выбранные изменения ядра отдельно, не смешивая SDK.
