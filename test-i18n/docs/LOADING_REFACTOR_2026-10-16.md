# Загрузка EN/TR: явные пути и готовые текстуры

Рабочая ветка: `base`. Сравнение с исходным `base` a7c636a1a85ffb3e2f923228ca13621cdffa0d4b и рабочим RU-корнем `main` 516942dfbe4a33ed16103779ebe7b4937532b20b. RU-корень взят из чистого git archive для локального read-only сравнения; main не изменялся. Публичный test-i18n не обновлялся.

## Изменения

- Общая функция imagePath в vertical_slice выбирает локализованный URL до штатного image() Phaser. Больше нет перехвата LoaderPlugin.addFile.
- 16 готовых WebP в assets/i18n/ready уже имеют исходные sourceSize и те же поля contain. Убраны drawImage → textures.remove → addCanvas для всех 10 видов языковой графики во время игры. Исходники и старые веб-копии сохранены.
- src/i18n/ui.js содержит явные методы result/shop/prepare. Runtime вызывает их при построении собственного UI; стенд больше не оборачивает resultPopup, Map.openPaidShop или Play.openPaidShop и не ищет контейнеры для декорирования постфактум.
- Скрипты запрашиваются параллельно, исполняются по порядку через async=false. Шрифт загружается параллельно; первый Title его не ждёт. До startupReady создаются кешированные золотые заголовки победы, поражения и платной лавки. При открытии результат не ждёт шрифт или Canvas-рисование.
- Удалён служебный опрос установки обёрток. Его прежний 10-секундный лимит не должен выдавать ошибку стенда из-за медленной фоновой загрузки.
- Размеры, относительные якоря, дуги/цвета/шрифт и схема FIT1920×1080 сохранены. Комбо уже было ограничено2550ms; параметры не изменялись, тест подтверждает все duration+delay и прежние180конфетти/53звезды.

## Сначала сравнение, затем изменение

До правок сопоставлены main/index.html, main/src/vertical_slice.js и свежий base. Выполнены по три локальных запуска рабочего RU, SDK-free RU и прежних EN/TR. В исходном стенде действительно присутствовали дополнительные6 CanvasTexture на старте; обычный drawImage занимал только9–21ms суммарно. Это не объясняет минуту ожидания само по себе.

После изменений проведено отдельное последовательное сравнение без параллельных браузерных QA. Chromium, HTTP на localhost, мобильный viewport915×412 DPR2, одинаковые браузер/сеть. Первый запуск — свежий context; следующие два — повторная навигация с HTTP-кешем (transferSize=0 у ресурсов). Это эмуляция с программным рендерингом, не физический Android и не GitHub Pages.

Первый Title здесь означает обнаруженную активную сцену Title, а не аппаратный замер фактического первого пикселя. startupReady — готовность карты/core плюс шрифтов и заголовков; это не готовое поле. Числа отдельных запусков не являются обещанием скорости на устройстве пользователя.

Дополнительные6 вызовов addCanvas языковой графики занимали114–140ms CPU submission на старте; после их0. Измерен texImage2D CPU submission, а не завершение GPU. Сетевая часть отражена отдельно в resource timing; точное отделение внутреннего image.decode от последующей GPU-работы не заявляется. Ожидание звука проверено отдельным искусственным удержанием всехMP3.

Длинные data: URI встроенного шрифта в JSON заменены маркером с длиной; времена/байты сохранены. Сырые данные: docs/qa/loading_refactor_comparison_2026-10-16.json. Скрипт: scripts/compare_loading_browser.cjs; нужны BERRIES_REFERENCE_RU и BERRIES_REFERENCE_BASE — каталоги чистых git archive. Для браузера используются стандартные BERRIES_PLAYWRIGHT_MODULE/BERRIES_BROWSER_EXECUTABLE/BERRIES_BROWSER_ARGS.

## Компромиссы и следующий шаг

Полный выбранный языковой набор (включая ленивые окна) вырос с~1,36 до2,03MB, потому что графика уже имеет утверждённые большие размеры. Это цена удаления runtime-нормализации; GPU-память нормализованной картинки не уменьшена. Не заменять это утверждением о снижении всей сети или памяти. Общий арт по языкам не дублируется.

Минутный запуск пользователя не воспроизведён; результаты не доказывают устранения его причины. Следующая необходимая проверка — сайт пользователя и физический Android с network trace. Полный последний ход/каскад→видимый результат отдельно от прямого вызова resultPopup не измерен этой таблицей.

Остаются: перенос выбора словарей/манифеста из тестового bootstrap в полноценную общую точку входа, ручная смена языка/общий прогресс, release allowlist общей сборки. Стенд намеренно сохраняет тестовый storage prefix; он не переносился в основную игру. GamePush/реальные платежи/новые карты и герои не подключались.
