# «Безумные ягодки» — РСЯ + покупки в собственной веб-версии
Актуально на 19.10.2026. **Ветка-кандидат:** `feature/web-monetization`. Живая `web/kingdom1` и эталон не изменены.

## Решение по форматам
1. **Rewarded** — первый приоритет после выдачи доступа РСЯ. Сценарии уже есть в игровой оболочке: удвоение награды после победы; дополнительная попытка после проигрыша; жизнь при нуле жизней. Не менять существующий игровой баланс и ограничение между рекламами. Не вводить дополнительные «100 монет по рекламе», пока продукт не утверждён.
2. **Баннер** — разместить на существующей карточке `https://kingdom1.ru/games/berries/` либо на отдельной доступной лендинг-странице, в видимом DOM вне игрового canvas. В `/play/` нельзя задвигать/уменьшать поле, накрывать кнопки, прятать рекламный блок в `display:none`, добавлять баннер на паузе поверх сцены. Выбор реального места после согласования архитектуры сайта.
3. **Полноэкранный обычный (без награды)** — НЕ вставлять между Phaser-сценами на десктопе. РСЯ ограничивает десктопный полноэкранный блок межстраничными переходами. Нужна предварительная проверка применимого формата в поддержке, после чего отдельный сценарий QA; сейчас запрещён.
4. Отсутствие рекламы или блокировщик рекламы не должно блокировать прохождение уровней и работу локальных сохранений.

## Что реализовано в кандидате
- `src/site/web-config.js` — сайт-провайдер включён, **все рекламные и платёжные возможности выключены**.
- `src/platform/web.js` — отдельный от Яндекс Игр адаптер. Rewarded использует реальный `Ya.Context.AdvManager.render({type:'rewarded', platform, blockId, onRewarded, onError})` только после конфигурации и испытаний; desktop/touch выбирается из `getPlatform()`.
- Награда возвращается только при официальном `onRewarded(true)`. Cancel/ошибка дают `false`; повторный callback не даёт повторную выдачу. Логика дедупликации, eligibility и паузы остается в `src/platform/platform.js`.
- Нет ручного SDK GamePush или Яндекс Игр. Нет демонстрационных block IDs. Нет имитации покупок. Нет auto-interstitial.
- `tests/web-monetization.cjs` проверяет безопасное выключенное состояние и смоделированные callback. Без реального рекламного блока/его тестовой среды это **не доказательство** корректной работы rewarded на устройствах.

## Подключение РСЯ — что должен сделать владелец
1. В кабинете РСЯ `Реклама на сайтах → Сайты → Добавить сайт`: проверить, какой именно host и площадка зарегистрированы. `berries.kingdom1.ru` и `kingdom1.ru` не считать автоматически одним рекламным сайтом. Дождаться статуса **Активно** — до этого доход не начисляется.
2. Подтвердить домен в кабинете предложенным способом (ads.txt из кабинета или Вебмастер). **Нельзя сочинять ads.txt**, брать только реальную строку из кабинета.
3. Обратиться в поддержку РСЯ за допуском **Rewarded**, пояснив игровую механику, названия бонусов и отсутствие принудительного просмотра.
4. После доступа создать **два Rewarded блока**: desktop + touch. Сохранить выданные `R-A-…` и точный код загрузчика РСЯ.
5. Для сайта/карточки игры отдельно создать **баннер** (один идентификатор может работать для desktop и touch; проверить допустимые размеры конкретного блока).
6. Прислать только публичные IDs и сгенерированный JS-код **без паролей кабинета**. После этого разработчик подключит загрузчик РСЯ один раз в `head`, внесёт IDs в конфигурацию и проведёт реальный тест до переключения `rewardedApprovedAndTested` на `true`.
7. Протестировать: desktop, телефон, блокировщик рекламы, отказ, закрытие до вознаграждения, onRewarded(true), двойной клик, пауза/звук, возвращение во вкладку, отсутствие зависания рекламы, fullscreen/PWA.

**Критично:** нет поддерживаемого универсального `onClose` именно для Rewarded в документации callback-функций. Не эмулировать завершение рекламы таймером и не включать боевой флаг до живой проверки возврата управления после `onRewarded`.

## Собственный магазин — серверная часть обязательна
Товары из текущей игры:
| ID | Содержимое | Старая цена Яндекс Игр — НЕ цена веб-сайта |
| -- | -- | -- |
| `coins_1000` | 1000 монет | 99 ₽ |
| `lives_5` | восстановление до 5 жизней | 149 ₽ |
| `boosters_3` | по 3 бустера каждого типа | 199 ₽ |

Рекомендуемый платёжный провайдер для РФ — **ЮKassa**, поскольку поддерживает и самозанятых, и игровой цифровой контент. Выбор и реальные условия подключения нужно подтвердить в кабинете до написания production PHP-бэкенда. В сценарии оплаты при самозанятости формирование чека в «Мой налог» и передача его клиенту — отдельная обязанность; готовая форма ЮKassa не заменяет чек автоматически.

### Обязательный порядок оплаты
1. Сервер создаёт анонимную сессию/игровой профиль; нужен путь восстановления покупок, иначе при смене браузера или очистке `localStorage` платные товары будут потеряны.
2. Сервер выдаёт `GET /api/berries/catalog` с разрешёнными ID, официальными рублёвыми ценами и статусом товара. Не брать цены из браузера.
3. По `POST /api/berries/checkout` сервер валидирует продукт, защиту от CSRF, свой серверный тариф, создаёт `orderId` и заказ в ЮKassa секретным API-ключом (ключ хранить вне public_html), с идемпотентным идентификатором.
4. Игрок переходит к защищённой оплате/виджету. Закрытие, `postMessage`, URL `success` и возвращение с сайта платежей **не дают права начислить покупку**.
5. ЮKassa присылает `payment.succeeded` на HTTPS webhook либо сервер опрашивает API. Сервер повторно **проверяет подлинность события и точный статус через API**, сравнивает сумму, валюту, `orderId`, ID продукта и связанный профиль.
6. Только проверенный заказ выдаёт серверное одноразовое право на товар; в базе записать `paymentId` уникально, обработать повторные webhook идемпотентно и предоставить механизм получения незавершённых покупок после возврата/перезагрузки.
7. Сохранения сейчас браузерные: пользователь может подделать `localStorage`. Для защиты платного инвентаря и переносимости лучше серверный кошелёк/инвентарь или хотя бы серверные права и устойчивый восстановительный идентификатор. **Без этого веб-IAP не выпускать в production.**

### Статус
Frontend checkout **НЕ подключён** и не создаёт оплату; `capabilities.purchases=false`. Это сознательная защита, пока нет провайдера, API/backend, защищённых прав/сохранений и тестовых платежей.
Не пытаться начислять монеты через один `window.postMessage` и не хранить секрет ЮKassa в JS-файле.

## Ограничения релиза
- Экран 1920×1080 FIT, утверждённый визуал, отдельный fullscreen/PWA, без обрезки.
- Ветка `web/kingdom1` остаётся рабочей до проверки кандидата.
- Блоки и рекламные callback могут требовать HTTPS топ-level страницу (не внутри iframe), совместимость fullscreen проверяется отдельно.
- Перед монетизацией нужны корректные публичные документы, политика данных/cookies, условия цифровых покупок, контакт поддержки.
- Версия для VK/OK использует свой SDK и платежи; эту адаптацию не переносить туда автоматически.
