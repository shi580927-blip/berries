# PRODUCTION SPEC — «Безумные ягодки: Лесное королевство»

Версия: 0.1
Дата: 2026-09-13
Статус: ГОТОВО К ПРОВЕРКЕ

## 1. Цель документа
Зафиксировать production-структуру проекта до начала разработки: экраны, навигацию, UI-систему, адаптивность, размеры, safe areas, структуру GitHub и интеграцию с Яндекс Играми.

---

## 2. Целевые платформы и формат
- Платформа релиза: Яндекс Игры.
- Устройства: desktop + mobile.
- Основная ориентация: landscape.
- Базовая виртуальная сцена: 1920×1080, 16:9.
- Масштабирование: пропорциональное, без растяжения по одной оси.
- На неподдерживаемой ориентации используется системный/SDK-сценарий поворота устройства.
- Главный игровой экран должен полностью помещаться в доступной области без браузерной прокрутки.

### Базовые тестовые разрешения
Проверять минимум:
- 1366×768
- 1600×900
- 1920×1080
- 1920×1200
- 2560×1080
- 2560×1440
- мобильные landscape с различными соотношениями сторон и вырезами/системными зонами.

---

## 3. Правило SAFE AREA

### 3.1. Виртуальная координатная система
Все ключевые UI-элементы проектируются внутри виртуальной сцены 1920×1080.

### 3.2. Безопасная область
Внешние края экрана считаются зоной риска из-за отличий viewport, browser chrome, вырезов и адаптивного масштабирования.

Для master-layout принимаем:
- горизонтальный внутренний отступ: не менее 96 px;
- вертикальный внутренний отступ: не менее 54 px;
- для крупных основных кнопок желательно 120 px от левого/правого физического края;
- никакие кнопки, тексты, цели, счётчики или препятствия не должны быть обрезаны.

Эти значения являются нашей внутренней дизайн-сеткой, а не утверждением о фиксированном safe area Яндекс Игр. В коде дополнительно учитывается фактический viewport.

### 3.3. Главное правило мобильной версии
Игровое поле нельзя уменьшать из-за слишком крупных декоративных кнопок.
При недостатке ширины сначала:
1. уменьшается декоративный воздух;
2. уменьшаются боковые панели;
3. упрощается декор;
4. масштабируются второстепенные кнопки;
5. игровое поле сохраняет приоритет и остаётся полностью доступным.

## 4. Сетка игрового экрана

### 4.1. Desktop 1920×1080
Рекомендуемая композиция:
- левый блок целей: 260–300 px;
- центральная игровая зона: до 800–860 px;
- правый блок бустеров/маскота: 250–300 px;
- промежутки между блоками: 24–40 px;
- верхняя зона HUD: около 110–140 px;
- нижняя зона действий: около 110–140 px.

### 4.2. Mobile landscape
Не создавать отдельную «маленькую копию desktop». Используется тот же 16:9 layout, но с responsive-перестройкой размеров.

При узком viewport:
- игровое поле центрируется;
- цели остаются слева компактным блоком;
- бустеры справа компактной вертикальной колонкой;
- маскот уменьшается или временно скрывается, если мешает полю;
- декоративные таблички можно скрывать;
- кнопки «Назад» и «Магазин» уменьшаются, но остаются легко нажимаемыми.

### 4.3. Размер клетки
Для 8×8 поля целевой визуальный размер клетки в master-layout: ориентир 88–100 px.
Точное значение определяется после тестовой сборки на 1366×768 и мобильном landscape.

Важно: ягоды и препятствия масштабируются только пропорционально.

## 5. Ключевые экраны MVP

### S01 — Boot / Loading
Содержит:
- фон или фирменную заставку;
- индикатор загрузки при необходимости.

Логика:
- загрузка SDK;
- загрузка минимального набора ресурсов;
- восстановление сохранения;
- после фактической готовности сообщить платформе о завершении загрузки.

### S02 — Main Menu
Содержит:
- логотип;
- кнопка «Играть»;
- настройки;
- помощь;
- при необходимости вход/профиль через Яндекс ID отдельной добровольной кнопкой.

Не перегружать магазином и рекламой до первого игрового действия.

### S03 — Карта уровней
Уже утверждённый базовый экран.

Содержит:
- монеты;
- жизни;
- заголовок карты;
- дорожку уровней;
- состояния нод: open/current/completed/locked;
- большую CTA «Полетели!»;
- «Назад»;
- «Магазин»;
- маскот/декор только если не мешает мобильной safe area.

Кнопки уровней — графика без цифр. Цифры накладываются программно.

### S04 — Level Intro / Pre-level
MVP-вариант может быть popup поверх карты, а не отдельная сцена.

Содержит:
- номер уровня;
- цели;
- доступные pre-level бустеры;
- «Играть».

Для самых первых уровней допустим переход сразу в GameScene, если обучение показывается внутри уровня.

### S05 — Game Screen
Уже утверждённый базовый экран.

Содержит:
- поле 8×8;
- число ходов;
- цели;
- бустеры;
- монеты/жизни либо компактный HUD;
- пауза;
- маскот и декоративные элементы только вне активного поля.

На основном игровом экране нет браузерной прокрутки и нет необходимости свайпать UI, чтобы увидеть обязательное действие.

### S06 — Win Popup
Поверх затемнённого игрового экрана.

Содержит:
- победа;
- заработанные монеты;
- прогресс/звёзды, если система будет утверждена;
- CTA «Дальше»;
- опционально rewarded «×2 монеты за рекламу».

### S07 — Lose / Continue Popup
Уже утверждённый концепт.

Содержит:
- «Почти получилось!»;
- что осталось собрать;
- крупный CTA «+5 ходов за рекламу»;
- явное указание, что будет реклама и какая награда выдаётся;
- «Переиграть»;
- «На карту».

Rewarded — только добровольный.

### S08 — Shop
Вкладки/секции:
- монеты;
- бустеры;
- жизни;
- премиум / темы.

Покупки за реальные деньги реализуются только через платежные механизмы Яндекс Игр.

### S09 — Premium Offer
Открывается после достижения 3 уровня.

Разовая покупка.
Состав текущей версии:
- Королева;
- премиальная тема;
- отдельный фон/рамка;
- немного монет;
- небольшой набор бустеров.

Не блокирует прохождение бесплатной игры.

### S10 — Settings / Pause
- музыка on/off;
- звук on/off;
- продолжить;
- на карту;
- при необходимости язык.

## 6. User Flow MVP

Boot
→ Main Menu
→ Map
→ Level Intro
→ Game
→ Win → Map/Next
или
→ Lose → Rewarded +5 moves → Game
или
→ Lose → Replay / Map.

Дополнительные ветки:
- Map → Shop → Map;
- после 3 уровня → Premium Offer → покупка/закрытие → Map;
- Game → Pause → Game/Map.

## 7. UI DESIGN SYSTEM

### 7.1. Базовые компоненты
- PrimaryButton — зелёный главный CTA;
- SecondaryButton — дерево/коричневый;
- BlueButton — навигационный/вторичный;
- Danger/ReplayButton — красный при необходимости;
- CurrencyPill;
- LifePill;
- GoalPanel;
- BoosterButton;
- LevelNode;
- ModalPanel;
- Toast/RewardMessage;
- SettingsIconButton.

### 7.2. Кнопки
Графический фон кнопки желательно хранить отдельно от текста.
Текст рисуется программно, чтобы:
- локализовать RU/EN;
- не создавать отдельные PNG под каждую надпись;
- корректно масштабировать интерфейс.

### 7.3. Touch target
Внутренний production-стандарт:
- целевой минимум интерактивной зоны на мобильном: около 48 CSS px;
- визуальная кнопка может быть меньше hit-area, но не наоборот;
- между соседними активными кнопками оставлять зазор.

### 7.4. Текст
- основные CTA крупные и короткие;
- мелкий декоративный текст не несёт критичной функции;
- контраст текста проверяется на ярком фоне;
- надписи не запекаются в фоновые изображения, если должны локализоваться.

---

## 8. Ассеты и рендеринг

### Master
- игровые квадратные элементы: 512×512 PNG RGBA;
- персонажи: 1024×1024 или крупнее, затем экспорт под игровые размеры;
- фоны: master минимум 1920×1080, предпочтительно 2560×1440 для запаса;
- UI-панели и кнопки: PNG с прозрачностью или 9-slice там, где возможно.

### В игре
Никогда не растягивать изображение независимо по X/Y.
Использовать uniform scale.

Лёд:
- overlay над content;
- одинаковая геометрия ice_1 и ice_2;
- центр остаётся достаточно прозрачным, чтобы ягода/жёлудь читались.

## 11. Yandex Games integration — production checklist

Обязательные/критичные пункты для нашей реализации:
- SDK подключён;
- игра доступна без обязательной сторонней регистрации;
- если используется авторизация Яндекс ID — только после осознанного действия пользователя;
- guest progress сохраняется;
- при потере фокуса/рекламе игровой процесс и звук останавливаются;
- progress сохраняется после значимого изменения;
- интерфейс корректно реагирует на изменение доступной области;
- нет browser scroll / swipe-to-refresh внутри игры;
- кнопки, тексты, препятствия, индикаторы не обрезаются и не перекрываются;
- rewarded вызывается только добровольно и заранее ясно показывает конкретную награду;
- покупки только через Яндекс Игры;
- orientation в draft: Landscape;
- LoadingAPI.ready вызывается после фактической готовности игры;
- GameplayAPI.start при старте/возврате в игровой процесс;
- GameplayAPI.stop при паузе, окончании уровня, уходе вкладки и перед рекламой.

## 12. Rewarded advertising points

MVP:
1. LosePopup → +5 ходов.
2. WinPopup → ×2 монеты.
3. Нет жизней → +1 жизнь.
4. Pre-level → бесплатный бустер (позже, если не перегружает первый релиз).

Нельзя:
- вызывать rewarded без действия игрока;
- маскировать rewarded под обычную кнопку;
- обещать одну награду и выдавать другую;
- делать просмотр обязательным для продолжения основной игры.

## 13. Сохранения

Сохранять как минимум:
- текущий открытый уровень;
- результаты пройденных уровней;
- монеты;
- жизни и время восстановления;
- бустеры;
- покупки;
- premium entitlement;
- выбранный маскот;
- выбранная тема;
- настройки звука/музыки;
- язык.

Триггеры сохранения:
- победа;
- покупка/расход ресурса;
- получение rewarded-награды;
- смена темы/маскота;
- изменение настроек;
- уход в фон при возможности.

---

## 14. Responsive acceptance tests

Перед релизом каждый ключевой экран проверяется:
- минимум на desktop 1366×768 и 1920×1080;
- на широком desktop 2560×1080;
- на нескольких mobile landscape viewport;
- после resize окна;
- при переходе portrait ↔ landscape;
- с длинными RU и EN строками.

Критерии:
- поле полностью доступно;
- ничего обязательного не закрыто;
- кнопки не попадают поверх match-3 клеток;
- нет деформации графики;
- нет перекрытия текста;
- нет прокрутки страницы;
- все CTA нажимаются пальцем;
- rewarded-предложение однозначно читается.

## 15. Что пока НЕ делаем
- portrait gameplay;
- сложную анимацию персонажей;
- 100+ уровней;
- много премиум-паков;
- обязательные interstitial в активном gameplay;
- сложную систему коллекций;
- отдельную backend-инфраструктуру без реальной необходимости.
