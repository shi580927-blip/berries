# GamePush — чек-лист подключения и приёмки «Безумных ягодок»
Дата проверки документации: 16.10.2026. Статус: исследование и план интеграции; SDK, реклама, облако и покупки НЕ подключены и НЕ приняты.
Ветка: platform/gamepush. Начало: эталон reference/sdk-free-2026-10-16, коммит25836d8fb34b9270206d2ad54534db53ffb5efbb; игровой код f5610ad.
Эталон и рабочий RU-корень main не менять. Прямой сайт с РСЯ ведётся отдельно в web/kingdom1.

## 1. Что является требованием, а что нашим решением
[GP01–GP10] — официальные страницы ниже; перед подключением перепроверить актуальные сигнатуры/код из своего кабинета. Все пункты [] — задания, не отчёт об успешных тестах.
Наши рекомендации: отдельный адаптер, единый владелец наград, раздельные тестовые сохранения/домены и измерение регрессий. GamePush SDK не отменяет правил конкретной площадки; его общий checklist содержит платформенные оговорки и не является единым договором модерации для всех.

## 2. ДО подключения SDK: обязательный входной контроль
- [x] Зафиксирован эталон без SDK и отдельная ветка; опубликованный test-i18n не заменяется автоматически.
- [ ] Выбрать первые площадки и составить матрицу: язык/название, реклама/покупки/вход/облако, внешние ссылки, ориентация, возрастная категория, промоматериалы. Проверять правила Яндекса/VK/ОК непосредственно перед соответствующей публикацией.
- [ ] Уточнить в кабинете, нужен только SDK или также GamePush backend/hosting/distribution; это разные услуги. Проверить актуальный тариф/квоты именно выбранных облачных функций; SDK не означает автоматически бесплатный backend.
- [ ] Создать проект; получить СВОИ projectId и publicToken/выданный код подключения, список включённых площадок и тестовых URL. Значения из примеров документации не копировать.
- [ ] Закрытые ключи/токены сервера не включать в клиент/репозиторий. Публичный publicToken предназначен для клиентского загрузчика.
- [ ] Добавить точные доверенные origins, включая протокол/порт localhost, staging; пометить тестовые сайты и проверить защиту от неизвестных hosts [GP03].
- [ ] Для изоляции staging предпочтителен отдельный origin: разные папки одного сайта имеют общее localStorage.
- [ ] Прогнать baseline RU/EN/TR: старт, сундук, карта, поле, все окна, next/retry/map, звук, пауза, смена размера; сохранить сетевой trace/кадровые замеры.
- [ ] Закрыть общий языковой bootstrap: сейчас index.html/менеджер готовы только для RU; EN/TR работают через docs-стенд с отдельными словарём и storage. Простая вставка SDK не превращает его в общий RU/EN/TR-релиз.
- [ ] Описать схему Campaign version1: done, coins, inventory, lives/nextLifeAt, daily, active/attemptId/serial, lastWin, purchaseTokens, updatedAt. Тестовый префикс berries_localization_preview_* в production не переносить.
- [ ] Решить владельца прогресса/синхронизации и миграцию до первого облачного write. Не автоматически сливать разные аккаунты или денежные балансы через max()/сумму.
- [ ] Проверить сборщик: текущий scripts/build_release.py собирает RU/local, а не GamePush. Запланировать отдельный allowlist и entrypoint без docs-отладки.

## 3. Схема в коде (проектное решение)
Общая игра → BerriesPlatform → адаптер gamepush → gp.*. Прямых gp/YaGames/VK обращений из игровых сцен не добавлять.
Предлагаемые новые файлы: src/platform/gamepush.js, platform-config/gamepush.*, отдельный entrypoint/сборщик и тесты адаптера. Имена пока план, файлы адаптера не созданы.
Один entrypoint выбирает одного владельца платформы. Не грузить параллельно старый Яндекс-адаптер, VK Bridge вручную и GamePush поверх него.
Нужное сопоставление:
| Наш контракт | GamePush / задача |
|---|---|
| init/languageReady | callback onGPInit, готовность игрока отдельно; язык gp.language |
| loadingReady | gp.gameStart() при действительной готовности нужной точки старта, не на download script |
| gameplayStart/Stop | gp.gameplayStart()/gp.gameplayStop() по событиям игры |
| pause/sound | gp pause/resume и состояние звука → существующий BerriesLifecycle |
| showRewardedVideo | gp.ads.showRewardedVideo(), единичный подтверждённый исход |
| restore/save/flush | выбранное хранилище, schema/migration, подтверждённый sync |
| catalog/purchase/restore | gp.payments; отдельная приёмка до включения capability |
Режим unsupported/unavailable — явный возврат в интерфейс, без бесконечного ожидания и без начисления денег/предметов.

## 4. Инициализация, язык и жизненный цикл [GP01, GP02, GP04, GP09]
- [ ] Callback зарегистрирован до загрузчика; init выполняется один раз, используется актуальный выданный loader с его fallback-механизмом.
- [ ] До работы с профилем/его записью дождаться gp.player.ready. Не путать загрузку скрипта, готовность SDK, игрока и графики.
- [ ] SDK/player timeout имеет понятную ошибку/повтор; не перезаписывает облако новым пустым Campaign. Если разрешён local-only режим, явно не выдавать его за облачную сессию.
- [ ] gp.language применяется до выбора словаря/арта. Ручной выбор сохраняется; неподдерживаемые языки получают заранее согласованный fallback. Проверить ru/en/tr, en-US/tr-TR, неизвестный код; русский title/лого пока сохранить.
- [ ] Меню/карта не считаются активным уровнем; begin/end события не дублируются после restart.
- [ ] События gp pause/resume не зацикливают вызовы gp.pause()/resume(). Снятие одной причины паузы не снимает visibility/ad/purchase/orientation причины.
- [ ] Reward не означает закрытие рекламного окна: игру/звук не возобновлять, пока оверлей реально открыт.
- [ ] Подписки SDK создаются один раз или снимаются при shutdown; 20 переходов сцен не умножают callbacks.
- [ ] Retry/next/map — смена Phaser-состояний, не location.reload и не пересоздание iframe. Это отдельно отмеченная ловушка GamePush [GP09].
- [ ] Полноэкранный режим проверяется по возможностям браузера/контейнера; SDK не отменяет ограничения iOS.

## 5. Сохранения [GP04–GP06]
- [ ] Явно настроены поля в кабинете и подходящее хранилище для каждой площадки; не предполагать одинаковую поддержку platform storage везде.
- [ ] До выбора local/remote сделать backup; не использовать override:true как универсальную «починку».
- [ ] Проверить новый игрок/старый профиль/ошибка сети/гость/вход в аккаунт/смена аккаунта/второе устройство.
- [ ] Сохранить уровни21–30, монеты, запасы бустеров и восстановление жизней. Активный attempt не восстанавливать как уже выданную награду.
- [ ] При изменениях sync контролируется, ошибки видимы; важный прогресс сохраняется до ухода со страницы, а не только в pagehide.
- [ ] Две вкладки и offline→online не удваивают daily/покупки/награды; повторный sync не откатывает прогресс.
- [ ] Сверить размер сериализованного состояния и лимиты текущего хранилища; не класть графику/аудио в профиль.
- [ ] Не обещать общий прогресс GamePush↔сайт↔исторический Яндекс без отдельной идентификации и миграции.
- [ ] Проверить браузерные ограничения хранения/инкогнито: игра запускается, но долговечность локальных данных не обещается.

## 6. Реклама [GP07]
- [ ] Перед вызовом проверить доступность нужного формата; отказы/no-fill/AdBlock — штатные исходы.
- [ ] showRewardedVideo и fullscreen не перепутаны. В документации в одном примере опции rewarded встречается showFullscreen — не копировать эту строку как реализацию rewarded.
- [ ] Для текущей игры награды: удвоение lastWin, продолжение после поражения, восстановление жизни — только через разрешённый Campaign сценарий.
- [ ] Выбрать ОДИН источник подтверждения выдачи: reward event либо проверенный успешный результат Promise, не оба одновременно.
- [ ] Связать запрос с attemptId и типом награды; защита от двойного клика, повторного callback и позднего callback после смены уровня.
- [ ] На закрытие без reward/ошибку награда не выдаётся; уже заработанная победная награда не теряется.
- [ ] Interstitial — только разрешённые паузы конкретной площадки. Не включать автоматически preload/sticky из стартового примера.
- [ ] Не показывать незапрошенную рекламу поверх выбора rewarded на той же развилке; проверить ограничения каждой площадки.
- [ ] Sticky, если вообще нужен, резервирует реальную площадь и не накрывает цели/бустеры/кнопки. Для первого подключения можно оставить выключенным.
- [ ] Проверить ориентацию/фон/закрытие вкладки во время показа; не снимать паузу watchdog-таймером, если реклама ещё на экране.

## 7. Платежи — отдельный gate, не включать «заодно» [GP08]
- [ ] При выключенных платежах UI корректно сообщает о недоступности, без фальшивой цены/успеха.
- [ ] Составить mapping наших coins_1000/lives_5/boosters_3 в GamePush product id/tag и ID каждой площадки; одинаковое имя не создаёт товары автоматически.
- [ ] Использовать актуальный каталог/валюту, isAvailable и собственные данные кабинета. Не подставлять99/149/199₽ как цену любой площадки.
- [ ] Владелец начисления ровно один: автоматические действия GamePush либо Campaign grant; проверить, что не включены оба.
- [ ] Утвердить восстановление незавершённой покупки, уникальную транзакционную идентификацию, постоянный журнал выдач и порядок сохранение→подтверждение/consume по контракту интеграции.
- [ ] Текущий Campaign хранит только последние100 purchaseTokens: этого недостаточно считать бесконечное exactly-once восстановление доказанным. До запуска реальных платежей проверить устойчивую дедупликацию/серверный механизм.
- [ ] consumePurchase Яндекса не вызывать рядом с gp.payments.consume для той же операции.
- [ ] Проверить успешную оплату, отмену, ошибку, refresh после оплаты до подтверждения, повторный restore, две вкладки,100+операций, отсутствие сети.
- [ ] Старые fetchProducts-примеры не переносить вслепую: в текущей странице метод отмечен устаревшим, каталог доступен после init.

Для каждого теста записать commit, origin, platformId, язык, устройство/ОС/браузер, cold/warm, expected/actual, видео/console/network. Макет строки: ID | статус NOT RUN/PASS/FAIL | доказательство.
| ID | Сценарий | Условие PASS |
|---|---|---|
| G01 | Без SDK, GamePush, site-сборки | В каждой только свой провайдер; эталон не изменился |
| G02 | Медленный/недоступный SDK | Нет вечного boot, пустого облачного write и ложной награды |
| G03 | Title→сундук→карта→поле | Все переходы, hit-area и заголовки прежние |
| G04 | RU/EN/TR + fallback | Нет смешения слов/графики, обрезания TR/русского шрифта |
| G05 | Новый/старый/битый save | Баланс и пройденные1–30 сохранены либо безопасное восстановление |
| G06 | Смена языка | Общий прогресс внутри этой версии, без тестовых language prefixes |
| G07 | Вход/выход/смена профиля | Нет переноса платного баланса чужому игроку |
| G08 | Два устройства/две вкладки | Нет rollback/дублирования daily и покупок |
| G09 | Реальный последний ход→win/lose | Замерен видимый результат, а не только JS-создание |
| G10 | Reward success / cancel / no-fill / throw | Ровно одна награда только при подтверждении |
| G11 | Двойное нажатие/поздний reward | Один запрос; проверен правильный attempt |
| G12 | Ad + hidden + pause menu | Resume только когда сняты все причины паузы |
| G13 | 20 restart/next/map | Нет reload iframe, дублей listeners, обрыва загрузки звука |
| G14 | Аудио задержано сетью | Картинки/результаты не ждут MP3 |
| G15 | Комбо | Весь один всплеск<=2550ms,180конфетти/53звезды и alpha сохранены |
| G16 | Магазины/нет монет/большие числа | Корректны цены, остатки, все зоны закрытия |
| G17 | Физический iPhone/Android | Поворот, safe-area, фон/возврат, отсутствие выделения |
| G18 | Desktop Safari/Chrome/Firefox + целевые среды | Игра, SDK и реклама проверены в фактическом контейнере |
| G19 | Cold/warm + плохая сеть | Разделены SDK/player/fonts/images/audio, измерены кадры |

## 9. Частые сбои
| Симптом | Возможная причина | Проверка |
|---|---|---|
| gp undefined | callback поздно/loader заблокирован | Network, порядок scripts, выданные projectId/publicToken |
| Доверенный сайт не распознан | другой origin/порт/host iframe | Сверить фактический origin в кабинете |
| Прогресс стал нулевым | local создал save до player.ready | Запрет write до restore/выбора источника |
| EN/TR внезапно RU | менеджер эталона gated на RU | Общий i18n bootstrap до SDK |
| Две награды | Promise+event / две подписки | Один grant-owner и requestId/attemptId |
| Игра звучит под рекламой | смешаны pause и muted | gp state + BerriesLifecycle причины |
| После restart реклама молчит | перезагружен iframe | Только scene transitions [GP09] |
| Нет рекламы/цены | формат/платёж недоступны или кабинет не настроен | Capability и фактическая площадка, не эмуляция одного localhost |
| SDK быстро, попап всё ещё долго | кадры/GPU/tween | Замер видимого окна; не объявлять исправленным по Promise |
| Покупка снова начислена | усечён журнал/нет стабильного ID | Платёжный gate закрыт до устойчивой схемы |

## 10. Порядок работ и stop conditions
G0: записать baseline → G1: common i18n/save contract → G2: init/lifecycle/язык → G3: restore/sync → G4: rewarded → G5: остальные разрешённые форматы → G6: отдельные платежи → G7: реальная площадка/устройства/сборка.
Нельзя выпускать при потере сохранений, двойных наградах, незавершающейся паузе, SDK в эталоне, неподтверждённой покупке, обрезанных кнопках. Результат «SDK вставлен» не равен «принят для публикации».
От пользователя понадобятся projectId/publicToken или код loader, выбранные площадки, тестовые ссылки/настройки рекламы, решение по облаку и, только если нужны покупки, mapping товаров. Пароли и секретные серверные ключи в чат не требуются.
