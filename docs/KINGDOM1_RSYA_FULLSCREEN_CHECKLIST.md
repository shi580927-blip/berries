## 2. Как подключать РСЯ именно к сайту [Y01–Y05]
- [ ] В кабинете РСЯ добавить фактическую площадку/домен, пройти модерацию и проверить статус. Это отдельная настройка, не существующие покупки/реклама в Яндекс Играх.
- [ ] В РСЯ: «Реклама на сайтах → Сайты → Добавить сайт», указать домен, подтвердить владение (например, Вебмастер/`ads.txt`) и дождаться модерации. Создать блоки разрешено заранее, **но вознаграждение за показы начисляется только в статусе сайта «Активно»**. [Y06]
- [ ] Форма сотрудничества может быть «Самозанятый» для резидентов РФ: ИП только ради регистрации сайта в РСЯ не обязателен. Уточнить реальные налоговые/договорные обстоятельства, заполнить реквизиты и оформить договор через кабинет; не присылать паспорт/ИНН в чат. [Y07]

- [ ] Указать реальный HTTPS host, поддомены/зеркала при необходимости; проверить документы и настройки владельца площадки в его кабинете.
- [ ] Выбрать форматы ниже. Создать свои блоки и взять актуальный код; не использовать демонстрационные R-A из документации.
- [ ] Загрузчик РСЯ вставить ОДИН раз в head страницы игры, до использования window.yaContextCb / Ya.Context.AdvManager; URL/параметры брать из выданного кода.
- [ ] Сайт работает при отсутствии рекламной сети/AdBlock; нет вечного loader и нет фиктивной награды.
- [ ] Для fullscreen/rewarded создать desktop и touch блоки по документации. При вызове выбирать устройство через документированный getPlatform(), не по языку или размеру canvas.
- [ ] Отдельно проверить настройки автоматики/глобальных блоков сайта: они не должны неожиданно вмешиваться в активный уровень.
- [ ] Рекламные элементы — DOM, не рисунок в Phaser canvas. Их нельзя маскировать под игровой UI.

## 3. Важная граница: обычный fullscreen РСЯ ≠ interstitial SDK Яндекс Игр
РСЯ для сайтов описывает полноэкранные блоки и ограничивает размещение формата Полноэкранный SD на desktop межстраничным переходом [Y04]. Переход Phaser Play→Map внутри одной HTML-страницы не является автоматически таким переходом.
Поэтому нельзя заранее обещать допустимость полноэкранного блока после каждого уровня в SPA. Нужно подтвердить применимый формат/сценарий для этой игры у поддержки РСЯ, особенно desktop. Не добавлять reload страницы и не имитировать переходы для обхода ограничения.

Без этого подтверждения стартовый вариант:
1. Обычный баннер на карточке игры/в доступной зоне страницы, не поверх игрового управления.
2. Rewarded по понятной добровольной кнопке — после предоставления доступа и проверки callback/паузы.
3. Автоматический fullscreen внутри уровня/на произвольном таймере выключен.
Периодичность задаётся правилами/настройками формата; частота в примерах не универсальное разрешение. Во время матча незапрошенную рекламу не запускать.

Отдельные требования РСЯ [Y04]: не вмешиваться в рекламный код/кнопку закрытия, не накрывать объявление своими кнопками, не провоцировать случайные клики и не накладывать форматы. Не менять режим просмотра ради приоритетного показа рекламы. Fullscreen игры включается ради игры по выбору пользователя, а не для обхода рекламных ограничений.

## 4. Rewarded — что потребуется [Y02]
Доступ по умолчанию закрыт: запросить его в поддержке. Возможные игровые сценарии — удвоение награды или дополнительная попытка; начисление строго после подтверждения.
В текущей подробной документации callback называется onRewarded(isRewarded). true — подтверждение, false — нет награды. В иных кратких/старых материалах встречается onReward: не смешивать интерфейсы, сверять выданный код и актуальную страницу.

Схема, а НЕ готовый production snippet:
клик «Реклама — получить X» → один request, захват attemptId → пауза → выбор desktop/touch блока → render(type:'rewarded') → подтверждение onRewarded(true) → единственная выдача → возобновление только после корректного завершения рекламного сценария.
- [ ] Награда закреплена за верным attemptId и не выдаётся дважды при event/Promise/двойном клике.
- [ ] onRewarded(false), no-fill, блокировка и ошибка не увеличивают баланс.
- [ ] Момент выдачи награды и момент снятия паузы проверены отдельно.
- [ ] Для rewarded НЕ предполагать универсальный onClose: страница callbacks явно перечисляет его для fullscreen/overlay/Top/Floor, без rewarded [Y05]. Уточнить надёжный сигнал завершения для фактически выданного кода. До проверки корректного завершения не включать этот формат в production.
- [ ] Не снимать паузу по произвольным10/30сек, пока реальная реклама ещё видима.
- [ ] Пока доступ/контракт не подтверждены, существующие rewarded-кнопки честно недоступны; бесплатный основной игровой путь остаётся.
Для обычного fullscreen onClose документирован; onError и onRender имеют другой смысл и не доказывают просмотр/награду.

## 5. Ошибки РСЯ: диагностика [Y05]
| Симптом/код | Проверить | Безопасное поведение игры |
|---|---|---|
| Loader blocked / AdBlock / no-fill | Сеть, доступность провайдера | Продолжить без награды, убрать ожидание при подтверждённом отказе |
| WRONG_DOMAIN | Фактический host и площадку в кабинете | Не обходить подменой URL |
| BLOCK_NOT_FOUND / PAGE_NOT_FOUND | Свои ID и статус конфигурации | Не повторять запрос бесконечно |
| PAGE_DISABLED | Модерация/пауза площадки | Отключить показы, сохранить игру |
| RESPONSE_MISMATCH_BANNER_CFG | blockId, type, desktop/touch | Исправить конфиг по коду кабинета |
| CONTAINER_NOT_FOUND | DOM создан и не удалён переходом | Ждать готовый видимый контейнер |
| CONTAINER_IS_HIDDEN | Размер/видимость DOM | Не запрашивать показы в display:none |
| TOO_SMALL_CONTAINER | Реальный размер слота | Не втискивать баннер под canvas |
| warning в onError | Может быть загружена реклама с предупреждением | Не снимать паузу автоматически, если оверлей активен |
| Реклама пропала после fullscreen игры | Fullscreen выбран только для canvas | Проверить DOM/верхний слой и выбранный fullscreen root |
| После закрытия слышны два трека | Сняты все причины pause либо два resume | Единый lifecycle, сохранить muted-настройки |
Нельзя диагностировать только по отсутствию дохода после одного теста; боевые клики по собственной рекламе не использовать как тест.

## 6. Почему на iPhone есть поля
Разделить три вещи:
A. Панели браузера Safari — часть браузера.
B. Safe area — вырез/индикатор Home и защищённые зоны.
C. Letterboxing — поля от вписывания строго16:9 в другое соотношение сторон.
Fullscreen API может помочь A там, где он поддерживается; viewport/safe-area корректируют B. Он не меняет C без обрезания/деформации игры. Пример без safe-area: при844×390 поле16:9 занимает~693×390, остаётся~75px сбоку. Это корректный FIT, не ошибка загрузки.
Сохраняем1920×1080 и весь UI. Не включать ENVELOP/обрезание целей, не растягивать по X/Y независимо. Фон полей можно продлить отдельным декоративным фоном оболочки; это отдельная небольшая правка, не переделка игрового интерфейса.
Точный диагноз полей пользователя ещё требует screenshot/модели/iOS и проверки геометрии, а не догадки.

## 7. Полноэкранный режим: требования к реализации [F01–F05]
- [ ] Отдельная понятная кнопка «На весь экран», доступная в оболочке игры. Вызов requestFullscreen непосредственно из пользовательского жеста, ДО await загрузки/SDK.
- [ ] Проверять существование метода и fullscreenEnabled, обрабатывать reject/fullscreenerror. Не считать переключение успешным до fullscreenchange.
- [ ] Выбирать подходящий общий DOM root, включающий canvas и рекламные/служебные DOM-потомки; fullscreen только canvas может спрятать рекламу вне него. На реальном устройстве проверить работу слоя РСЯ; не менять/не переносить внутрь canvas чужой рекламный UI.
- [ ] Встроенный iframe, если будет, требует корректной Permissions Policy и allowfullscreen/allow='fullscreen'; для прямой версии предпочтительна отдельная top-level страница.
- [ ] Не входить повторно автоматически после рекламы: пользовательская активация может быть утрачена. Показывать кнопку, не зацикливать запросы.
- [ ] GamePush full-screen API не применять в web/kingdom1; он нужен только ветке GamePush и не обходит ограничения браузера.
- [ ] screen.orientation.lock — лишь best effort после доступного fullscreen, с обработкой отказа. Нельзя обещать принудительный landscape на всех iPhone; оставить подсказку поворота.
- [ ] Переключение fullscreen не создаёт новый Phaser.Game, не сбрасывает поле/прогресс и не перезагружает URL.

### iPhone: основной fallback
Универсальный requestFullscreen для произвольного canvas/DOM на iPhone нельзя обещать: поддержку проверять на конкретном iOS/браузере. WebKit-задача о Fullscreen API для iOS остаётся открытой на дату проверки [F02]. Полноэкранное видео не является полноэкранным режимом интерактивной игры.
В обычной Safari-вкладке нельзя надёжно приказать браузеру убрать все панели. Если fullscreen недоступен — дать инструкцию «Поделиться → На экран “Домой” → открыть как веб-приложение» (названия зависят от iOS) и запуск с иконки [F03]. Это выбранный пользователем отдельный режим, не автоматический перевод открытой вкладки.
План оболочки: manifest c display:'standalone', именем/иконками/start_url/scope; совместимые Apple meta. Предпочесть запуск без панели браузера; не обещать убрать системный Home indicator/safe-area или поля16:9. Service worker ради одного standalone не обязателен; если добавится для offline, рекламу/SDK и личные ответы не кешировать.
Не принуждать к экспериментальным флагам Safari; не использовать видео/fullscreen или прокрутку1px как обещанный обход.

## 8. Viewport/масштаб: задачи web-ветки [F04, F05]
Сейчас styles.css использует height:100%, а index уже имеет viewport-fit=cover, ResizeObserver и scale.refresh. Новый fullscreen сам по себе проблему всех размеров не решает.
- [ ] В оболочке измерять доступный viewport:100dvh с совместимым fallback; проверить реальную visualViewport.width/height и её resize/scroll. Не использовать только screen.height или один100vh.
- [ ] Учесть env(safe-area-inset-*) один раз, не дважды; фон может заполнять экран, важные кнопки — в безопасной области.
- [ ] Изменение размеров хоста → Phaser scale.refresh, FIT; координатыpointer/hit-area остаются правильными.
- [ ] Refresh после fullscreenchange, orientationchange, visualViewport resize, возврата из рекламы/фона; не бесконечный цикл ResizeObserver.
- [ ] После поворота дождаться стабилизации размеров; не прятать уже отрисованную игру навсегда.
- [ ] В Safari проверить развёрнутую/свернутую панель, zoom и экранную клавиатуру, если появятся поля ввода.
- [ ] touch-action/user-select ограничивать игровой областью; не ломать прокрутку/клики официальной рекламы и меню «На экран Домой».
- [ ] В standalone кнопки выхода/навигации работают; нет «ловушки» в недоступном fullscreen.
Псевдокод обработчика:
если уже fullscreen → exitFullscreen;
иначе если API разрешён → requestFullscreen из текущего click, catch→fallback;
иначе → показать инструкцию standalone.
Это спецификация, не проверенный на iPhone готовый код.
